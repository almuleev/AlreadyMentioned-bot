# AlreadyMentioned

AlreadyMentioned — самостоятельно размещаемый Telegram-бот для чатов поддержки. Он показывает ранее сохранённый ответ администратора прямо в reply на новый вопрос и оставляет ссылку на оригинал; новые ответы не генерирует.

**Статус: локальный MVP.** Ответ администратора через reply на подходящий текстовый вопрос сохраняется автоматически и без сообщения бота. Бот сравнивает новые вопросы на русском языке только с решениями того же чата и показывает один ответ, если сходство достигает порога этого чата.

Подробные правила работы, настройка порога и объяснение оценок сходства — в [руководстве на русском](docs/GUIDE.ru.md). Устройство кода, запуск и точки расширения описаны в [руководстве для разработчика](docs/DEVELOPMENT.ru.md).

Основная embedding-модель — полная FP32 FRIDA.

Рабочий поиск поддерживает FRIDA + MiniLM: сначала пять кандидатов FRIDA,
затем оценка пары «вопрос — ответ» и смесь 75/25. Полный и содержательный
частичный ответ считаются полезными; при калибровке приоритет отдаётся
полноте. Режим выбирается `SEARCH_MODE=hybrid` или `baseline` для исходной
FRIDA. Пороги режимов сохраняются отдельно; `/status` показывает активный,
а `/threshold` изменяет только его в текущем чате.
Подготовка кэша, проверка и откат: [активный поиск](docs/ACTIVE_SEARCH.ru.md).

Перед первым запуском подготовьте локальный
кэш; существующей базе E5 нужен полный пересчёт векторов с резервной копией.
Порядок локального и Docker-перехода: [миграция FRIDA](docs/FRIDA_MIGRATION.ru.md).

## Структура

- `src/already_mentioned/bot/` — создание aiogram-бота и проверка прав.
- `src/already_mentioned/handlers/` — команды, сообщения и кнопки оценки.
- `src/already_mentioned/services/` — временная память reply-цепочек, фильтр вопросов, локальные embeddings и поиск.
- `src/already_mentioned/database/` — подключение к SQLite и схема таблиц.
- `src/already_mentioned/repositories/` — операции с данными чатов, решений и оценок.
- `src/already_mentioned/models/` — структуры данных, возвращаемые репозиториями.
- `tests/` — автономные тесты без Telegram-токена и скачивания модели.

## Локальная установка (Python 3.12)

В PowerShell из папки проекта:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -e ".[dev,rerank]"
Copy-Item .env.example .env
```

Заполните `TELEGRAM_BOT_TOKEN` в локальном `.env`. Путь к базе `DATABASE_PATH` по умолчанию — `data/already_mentioned.db`. Не добавляйте `.env` в Git. Если в Windows или переменных окружения настроен HTTPS-прокси, бот использует его для Telegram. Подготовьте закреплённые кэши FRIDA и MiniLM до запуска по инструкции [активного поиска](docs/ACTIVE_SEARCH.ru.md). Вычисления выполняются локально вне основного event loop; обе модели прогреваются перед polling. Импорт модулей и тесты модель не скачивают.

Для автосохранения бот должен получать обычные сообщения группы: отключите Privacy Mode в BotFather. Публичные и приватные **супергруппы** дают прямые ссылки на сообщения; в обычной группе Telegram такой ссылки не предоставляет, поэтому сохранить решение там нельзя. Подходящий ответ администратора также хранится в памяти до 6 часов для необязательного ручного `/solve`; одновременно бот помнит не более 5000 таких цепочек.

Команды: `/start` и `/help` показывают справку; `/status` — число решений и текущий порог; `/solve` вручную сохраняет ответ на вопрос, не прошедший фильтр; `/undo` как reply на ответ удаляет одно решение; `/threshold 0.458` меняет порог этого чата; `/forget` запрашивает подтверждение удаления решений и оценок чата. Последние четыре команды доступны администраторам. Под ответом бота есть один ряд кнопок **👍 / 👎**; оценку может оставить только автор вопроса, один раз. После оценки или через час кнопки исчезают. Ссылка **📎 Оригинал** остаётся в тексте ответа. Начальный порог гибридного поиска — 0,371; отдельный исходный порог FRIDA — 0,458. [Калибровка](docs/FRIDA_CALIBRATION.ru.md) показала низкую точность; настройка не подтверждает готовность автоматических подсказок к выпуску.

Запуск long polling:

```powershell
python -m already_mentioned.main
```

## Docker Compose (локальное развёртывание)

Нужен Docker Desktop с Linux-контейнерами и Compose. Токен остаётся в игнорируемом файле `.env`. Перед запуском контейнера остановите локальный Python-процесс: один и тот же токен должен опрашивать Telegram только из одного процесса.

В Windows можно дважды щёлкнуть `start-docker.cmd` в папке проекта: файл пересоберёт образ, запустит бота и покажет состояние контейнера. Окно останется открытым до нажатия клавиши.

```powershell
docker compose build
docker compose up -d
docker compose logs -f bot
```

`docker compose down` останавливает контейнер. Именованные тома `bot_data` и `model_cache` сохраняют SQLite-базу и модель между запусками. **Не используйте `down --volumes`, если хотите сохранить данные.** У Docker отдельные база и кэш: файлы из Windows-папок `data/` и `models/` автоматически не импортируются. Порты наружу не открываются.

Чтобы посмотреть численную оценку сходства для вопроса, выполните `docker compose exec -T bot python -m already_mentioned.diagnostics "Ваш вопрос здесь?"`. Подробности — в [руководстве](docs/GUIDE.ru.md#как-посмотреть-значение-самому).

Если Telegram доступен только через прокси, задайте в `.env` переменную `HTTPS_PROXY` с адресом, доступным контейнеру. Для прокси, работающего на Windows `127.0.0.1`, может понадобиться `host.docker.internal` с тем же портом. Не публикуйте адрес прокси вместе с секретами.

## Проверки и приватность

Проверки не требуют токена:

```powershell
ruff check .
pytest
```

Бот сохраняет ответы администраторов на подходящие вопросы, вручную сохранённые пары, оценки и минимальные настройки чатов — **не всю историю переписки и не имена пользователей**. Таблицы создаются при запуске. `/forget` удаляет решения и оценки текущего чата только после подтверждения кнопкой; настройка порога остаётся. В `tests/fixtures/questions.py` есть 80 синтетических сообщений для автономных проверок. Эти тесты используют фиктивные векторы и не измеряют точность настоящей модели.
