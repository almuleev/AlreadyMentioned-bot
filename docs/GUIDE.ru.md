# Руководство по AlreadyMentioned

AlreadyMentioned — бот для Telegram-групп поддержки. Он **не пишет ответы сам**: текстовый ответ администратора на подходящий вопрос сохраняется автоматически, а бот цитирует его в reply на похожий новый вопрос в том же чате. Текущая версия — локальный MVP для текстовых сообщений преимущественно на русском языке.

## Начало работы

1. Создайте бота через BotFather и сохраните выданный токен в локальном файле `.env` как `TELEGRAM_BOT_TOKEN=...`. Не публикуйте токен и не добавляйте `.env` в Git.
2. В BotFather откройте `/setprivacy` для этого бота и выберите **Disable**: иначе Telegram не будет передавать боту обычные сообщения группы. Добавьте бота в тестовую **супергруппу** с возможностью читать сообщения и отвечать. Для сохранённых ответов нужны прямые ссылки на сообщения; в обычной группе Telegram их не предоставляет.
3. Запустите бота одним способом: Docker Compose (ниже) **или** локальный Python. Не запускайте два процесса с одним токеном одновременно: оба будут получать одни и те же обновления через long polling.
4. В группе отправьте `/start`, `/help` и `/status`. Последняя команда покажет число решений и порог этого чата. Старую историю бот не импортирует.

### Запуск и обслуживание на этом компьютере

Из папки проекта в PowerShell:

```powershell
docker compose up -d
docker compose ps
docker compose logs --tail 50 bot
```

`docker compose logs -f bot` показывает новые строки журнала до `Ctrl+C` (бот при этом продолжает работать). `docker compose stop` останавливает бота, `docker compose start` запускает снова. После изменения кода выполните `docker compose up -d --build`. Docker Desktop должен быть запущен; при его остановке бот тоже недоступен.

База и модель лежат в постоянных томах Compose `bot_data` и `model_cache`. Обычный `docker compose down` сохраняет их. **Не используйте `docker compose down --volumes`, если хотите сохранить решения.** При запуске непосредственно через Python используются папки `data/` и `models/` в проекте; это отдельное хранилище. Перед миграцией между способами запуска проверьте, какую базу вы переносите.

Перед обновлением или переносом базы создайте и проверьте резервную копию. Команды для локального запуска, Docker Compose и восстановления приведены в [документе разработчика](DEVELOPMENT.ru.md#резервная-копия-и-восстановление-sqlite). Копия содержит тексты сохранённых сообщений и оценки, поэтому храните её в защищённом месте.

Для локального запуска без Docker см. [README](../README.md). Токен читается из `.env`, образец настроек — [`.env.example`](../.env.example). Модель FRIDA работает локально без платного API. Кэш подготавливается отдельной командой до запуска; переход со старой E5 требует пересчёта сохранённых векторов с копией базы по [инструкции миграции](FRIDA_MIGRATION.ru.md). Пороги чатов сохраняются, но качество подсказок с ними нужно проверить заново.

## Как сохранить решение

В супергруппе достаточно **двух текстовых сообщений**:

1. Участник пишет вопрос: «Где открыть личный кабинет?»
2. Администратор отвечает **reply на этот вопрос**: «Откройте раздел „Личный кабинет“ на сайте».

Если исходное сообщение прошло фильтр вопросов, бот **молча сохранит** пару: служебного сообщения в группе не будет. Убедиться в результате можно через `/status`. Автосохранение требует текстового reply администратора и прямых ссылок на оба сообщения. Обычная благодарность или сообщение, не похожее на вопрос, автоматически не сохраняется.

Если вопрос не прошёл фильтр, администратор может вручную сохранить пару: ответить **reply на свой ответ** командой `/solve`. Команду нужно отправить в течение **6 часов**, пока бот помнит ответ в оперативной памяти; после перезапуска эта память очищается. Ручное сохранение подтверждает бот сообщением. Повторное сохранение той же пары не создаёт дубль.

Для отмены ошибочного сохранения администратор отвечает **reply на сохранённый ответ** командой `/undo`. Бот удаляет это решение и связанные оценки, затем сообщает о результате. `/forget` по-прежнему удаляет все решения чата после отдельного подтверждения. Для одного типа вопроса можно сохранить несколько разных пар. Если исходное сообщение позже изменили или удалили, бот не обновит сохранённый текст и ссылку автоматически.

### Просмотр и исправление решений

Администратор отправляет `/solutions` в нужном чате. Бот показывает до пяти последних сохранённых решений: ID, полный сохранённый вопрос, сокращённый ответ, ссылки на исходные вопрос и ответ, число оценок 👍 и 👎. Очень длинный список или вопрос может быть разбит на несколько сообщений. Следующие страницы открываются командой `/solutions 2`, `/solutions 3` и так далее; номер следующей и предыдущей страницы указан в списке. Если решений нет, бот сообщает об этом. Участники без прав администратора список не получают.

Чтобы исправить **одно** решение:

1. Вызовите `/solutions` и запомните ID нужного решения, например `42`.
2. Перейдите по ссылке «Ответ» у этого решения.
3. Ответьте **reply на то исходное сообщение** одной из команд: `/editquestion 42 Новый текст вопроса` или `/editanswer 42 Новый текст ответа`.
4. Дождитесь сообщения «Решение исправлено». Если ID не соответствует сообщению, на которое сделан reply, бот ничего не изменит.

При изменении вопроса или ответа бот заново кодирует изменённый текст действующей моделью с префиксом `passage:`. Вектор другого текста сохраняется. Исправление меняет сохранённый текст для **будущих** подсказок, но не редактирует исходное сообщение в Telegram и не переписывает ранее показанные подсказки. Ссылки продолжают вести к исходным сообщениям; если они удалены или недоступны, сценарий правки через reply выполнить нельзя. Оценки остаются у решения и не меняют порог или ранжирование.

## Что видит участник

На подходящий вопрос бот отправляет **один reply** с текстом сохранённого ответа в блоке цитаты. Под ним один ряд кнопок «👍» и «👎». Ссылка «📎 Оригинал» находится в тексте и ведёт к исходному сообщению администратора для проверки контекста. Очень длинный ответ сокращается до 3000 символов, полный текст остаётся доступен в оригинале. Ссылки на приватную супергруппу вида `t.me/c/...` открываются у людей, имеющих к ней доступ.

Если совпадение ниже порога или сохранённых решений нет, бот молчит. Он также игнорирует личные сообщения, сообщения других ботов, команды и сообщения без текста. Предварительный фильтр пропускает текст с кириллицей длиной не менее 7 символов, если в нём есть `?` или он начинается с типичных вопросительных слов и выражений вроде «как», «где», «подскажите», «не работает», «ошибка». Это простой фильтр, а не полное понимание языка: некоторые реальные вопросы без таких признаков бот пропустит. Ответ администратора, сохранённый или подготовленный к `/solve`, не считается новым вопросом для поиска.

Оценить **показанное предложение** может только автор вопроса, один раз. Другим участникам при нажатии показывается уведомление «Оценить ответ может только автор вопроса», без сообщения в чат. После оценки кнопки исчезают для всех. Без оценки они убираются примерно через час (проверка каждые 15 секунд); после часа новые оценки уже не принимаются. Ссылка на оригинал остаётся доступна. Срок удаления сохраняется при перезапуске: просроченные кнопки убираются после запуска бота. Во время остановки бота или при недоступности Telegram удаление задерживается. Повторное нажатие не меняет голос. Новое поведение действует для ответов, отправленных обновлённым ботом; кнопки прежней версии больше не принимают оценки. Оценки сохраняются для анализа человеком, **не обучают модель и не меняют порог автоматически**. Их итоговое число видно администратору в `/solutions`. Команды для просмотра численного score в Telegram нет.

## Как бот выбирает ответ

1. Проверяет, похоже ли новое сообщение на русский вопрос по описанному выше фильтру.
2. Кодирует новый вопрос локальной моделью `intfloat/multilingual-e5-small` с префиксом `query:`. При сохранении вопрос и ответ кодируются по отдельности с префиксом `passage:`. Векторы нормализуются. Для ранее сохранённых ответов вектор вычисляется при первом поиске в чате.
3. Считает **cosine similarity** между новым вопросом и сохранёнными вопросом **и ответом** каждой пары только этого чата. Это число показывает близость текстов по смыслу; оно не является вероятностью правильности ответа и не проверяет факты в нём.
4. Выбирает решение с наибольшим score среди обоих сравнений. Если он **не меньше** порога чата, отвечает на новый вопрос цитатой сохранённого ответа и кнопкой исходного сообщения; иначе молчит.

| Сейчас влияет на показ подсказки | Сейчас не влияет на score |
| --- | --- |
| Текст нового вопроса и прохождение предварительного фильтра. | Решения других чатов и имена авторов. |
| Тексты подтверждённых вопросов и ответов **этого** чата и локальная embedding-модель. | Голоса 👍/👎: они записываются, но не меняют ранжирование. |
| Порог чата и наибольший score среди его решений. | — |

Начальный экспериментальный порог FRIDA для нового чата — **0,458**. У каждого чата он свой; ранее заданные настройки при повторном входе бота сохраняются. `/status` показывает значение с тремя знаками; администратор меняет его командой `/threshold 0.458` (принимается число от 0 до 1, также допустима десятичная запятая). Более высокий порог даёт меньше подсказок и обычно меньше случайных совпадений. Более низкий даёт больше подсказок, но может предложить неподходящий ответ. Настройка действует на будущие поиски и не пересчитывает уже показанные сообщения. [Калибровка на предварительной разметке](FRIDA_CALIBRATION.ru.md) дала низкую точность — порог следует проверять в тестовом чате, а не считать надёжной настройкой для всех чатов.

После добавления поиска по ответам прежние значения score для конкретных вопросов могут измениться: бот берёт максимум двух сравнений. Проверьте порог на вопросах своего чата, в том числе на вопросах без подходящего решения. Молчание не всегда означает, что подходящего ответа нет: причиной может быть предварительный фильтр, отсутствие решения, недоступность бота или слишком высокий порог. Для начала проверьте `/status` и `docker compose logs --tail 50 bot`.

### Как посмотреть значение самому

В PowerShell **из папки проекта**, пока Docker Desktop и контейнер запущены, подставьте точный текст своего вопроса:

```powershell
docker compose exec -T bot python -m already_mentioned.diagnostics "Что на карьерной консультации происходит обычно?"
```

Команда покажет лучшее совпадение, текущий порог, сохранённый вопрос, ссылку и решение фильтра. Она не отправляет ничего в Telegram и открывает SQLite **только для чтения**. Текст проверяемого вопроса передаётся только запущенной локальной модели, а не сохраняется ботом. Число пересчитывается сейчас; посмотреть прежний score по сообщению без его точного текста нельзя, потому что бот не хранит историю запросов.

Если в базе несколько чатов, укажите ID нужного чата из Telegram, например:

```powershell
docker compose exec -T bot python -m already_mentioned.diagnostics --chat-id=-1001234567890 "Ваш вопрос здесь?"
```

Число `-1001234567890` здесь пример: замените его на ID своего чата. Для запуска без Docker используйте `.\.venv\Scripts\python.exe -m already_mentioned.diagnostics "Ваш вопрос здесь?"`: он читает **локальную** базу из `DATABASE_PATH`, которая может отличаться от базы контейнера. Диагностика моделирует обычное новое сообщение; для reply-сообщения администратора и команд у бота есть дополнительные правила обработки.

## Как «обучать» и улучшать качество

**Сейчас настоящего обучения модели нет.** Веса embedding-модели не меняются. Без изменения кода можно улучшать базу подтверждённых решений и настраивать порог каждого чата:

1. Отвечайте через reply на точные, актуальные вопросы. Если вопрос не прошёл автоматический фильтр, используйте `/solve`. Формулируйте исходный вопрос так, чтобы в нём была суть проблемы. Слишком общий вопрос вроде «Что делать?» даёт менее полезный пример, чем «Как восстановить пароль от кабинета?».
2. Если похожий вопрос не получил подсказку, убедитесь, что он прошёл фильтр, затем проверьте порог. Не снижайте порог только из-за одного примера: соберите также вопросы, на которые отвечать **не следует**.
3. Если вы автор вопроса, отмечайте кнопками полезные и ошибочные предложения в течение часа. Пока бот только сохраняет эти голоса; их анализ и настройка по ним выполняются вручную. В MVP нет панели аналитики и команды выгрузки оценок.
4. Для настройки составьте набор реальных или обезличенных проверочных вопросов: переформулировки с одним правильным решением, вопросы со схожими словами, но другим ответом, вопросы без решения и обычные сообщения. Сравните, сколько правильных подсказок и ошибок выходит при нескольких порогах. Меняйте порог небольшими шагами и повторяйте проверку после пополнения базы.

Для повторяемой офлайн-проверки фильтра и поиска есть команда `python -m already_mentioned.evaluation` с вымышленными примерами; порядок запуска описан в [документе разработчика](DEVELOPMENT.ru.md). Она не является командой Telegram-бота. При смене модели надо заново вычислить embeddings **всех** сохранённых вопросов и ответов: старые векторы нельзя надёжно сравнивать с векторами другой модели, даже если их размер совпадает. Обучение или дообучение модели на сообщениях чата в MVP не предусмотрено.

## Команды и данные

| Команда | Кто может использовать | Действие |
| --- | --- | --- |
| `/start`, `/help` | Все | Краткая справка. |
| `/solve` | Администратор | Вручную сохраняет цепочку «вопрос → ответ», если вопрос не прошёл фильтр. |
| `/undo` | Администратор | Как reply на сохранённый ответ удаляет одно решение и связанные оценки. |
| `/status` | Участник группы | Число решений и порог этого чата. |
| `/solutions [страница]` | Администратор | Постраничный список решений текущего чата с оценками. |
| `/editquestion ID новый текст` | Администратор | Как reply на исходный ответ исправляет вопрос и его embedding. |
| `/editanswer ID новый текст` | Администратор | Как reply на исходный ответ исправляет только сохранённый ответ. |
| `/threshold 0.458` | Администратор | Меняет порог только этого чата. |
| `/forget` | Администратор | Показывает кнопки подтверждения удаления или отмены. |

`/forget` удаляет **все** решения и оценки только текущего чата после нажатия «Удалить данные». Подтвердить может тот же администратор, который вызвал команду, в течение **5 минут**; после перезапуска бота подтверждение теряется. Настройка порога и запись чата остаются. Восстановить удалённое можно только из заранее сделанной резервной копии.

SQLite хранит заголовок и настройки чата, подтверждённые тексты вопросов и ответов, их ссылки и embeddings, а также голоса с Telegram ID проголосовавшего пользователя и ID вопроса, для которого была показана подсказка. Имена пользователей и всю историю переписки бот не сохраняет. Данные разных чатов используются раздельно. Файл `.env` содержит секретный токен и должен оставаться локальным.
