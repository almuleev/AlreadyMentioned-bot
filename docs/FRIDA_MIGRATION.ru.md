переведена на схему 3 и контракт FRIDA. В ней было **0 решений**; копия
`data/backups/before-frida-20261006.db` и итоговая база проверены.
Реальная FRIDA загружена из кэша и проверена на синтетических текстах.
Polling не запускался. Том Compose не менялся: Docker daemon недоступен.

Основная модель — полная FP32 `ai-forever/FRIDA`, ревизия
`850455b605544a944739b25f81ddf812b6e3d0d5`. Это тот вариант, который
сравнивался с INT8; квантование при запуске не выполняется.
Контракт: 1536 измерений, CLS, максимум 512 токенов, L2, float32-le.
Новые запросы — `search_query:`, сохранённые вопросы и ответы —
`search_document:`. Префиксы соответствуют [карточке модели](https://huggingface.co/ai-forever/FRIDA).

## Локальный запуск

1. Остановите **все** процессы бота, включая старую версию. Не запускайте
   polling до окончания пересчёта. Новые процессы дополнительно защищены
   блокировкой `DATABASE.lock`; не удаляйте этот файл во время работы.
2. Установите зависимости из корня проекта. Для CPU можно сначала поставить
   Torch из официального CPU-индекса:

```powershell
.\.venv\Scripts\python.exe -m pip install torch --index-url https://download.pytorch.org/whl/cpu
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"
.\.venv\Scripts\python.exe -m already_mentioned.services.embeddings --download-model
```

Последняя команда только подготавливает/проверяет модель, без Telegram и БД.
Для уже существующего кэша опустите `--download-model`. По умолчанию бот
работает только с локальным кэшем; тексты чатов не отправляются в Hugging Face.

3. Проверьте фактический `DATABASE_PATH`. Пример для стандартной локальной
   базы (CLI пересчёта не читает `.env`):

```powershell
.\.venv\Scripts\python.exe -m already_mentioned.database.reembed data/already_mentioned.db --backup data/backups/before-frida.db --bot-stopped
.\.venv\Scripts\python.exe -m already_mentioned.database.backup verify data/backups/before-frida.db
.\.venv\Scripts\python.exe -m already_mentioned.database.backup verify data/already_mentioned.db
```

Выбирайте новый путь копии для каждого запуска: существующий файл не
перезаписывается. Копия создаётся online backup API **до** обновления схемы.
Затем одной транзакцией пересчитываются оба вектора каждой пары во всех
чатах; проверяются размерность, конечность чисел, единичная норма, целостность
SQLite и внешние ключи. Метаданные FRIDA фиксируются вместе с векторами.
Тексты, ID, ссылки, даты, голоса и пороги не меняются. После сбоя векторы и
контракт остаются прежними, хотя принятие схемы версии 3 уже могло завершиться.
Повторный успешный запуск проверяет FRIDA-векторы без повторного кодирования.

4. Запустите `python -m already_mentioned.main` через `.venv`. Со старым
   контрактом или неполными/повреждёнными векторами запуск и диагностика
   завершатся до поиска. Для новой пустой базы пересчёт не нужен.
5. Проверьте несколько известных вопросов и вопросы без решения в тестовом
   чате. `diagnostics.py` использует ту же FRIDA и читает базу без записи.

## Docker Compose

Данные тома Compose отличаются от локального `data/`. Docker Desktop должен
работать. Из корня проекта:

```powershell
docker compose stop bot
docker compose build bot
docker compose run --rm --no-deps bot python -m already_mentioned.services.embeddings --download-model
docker compose run --rm --no-deps bot python -m already_mentioned.database.reembed /app/data/already_mentioned.db --backup /app/data/backups/before-frida.db --bot-stopped
docker compose run --rm --no-deps bot python -m already_mentioned.database.backup verify /app/data/backups/before-frida.db
docker compose run --rm --no-deps bot python -m already_mentioned.database.backup verify /app/data/already_mentioned.db
docker compose up -d bot
```

При любой ошибке не запускайте бот до выяснения причины. Не удаляйте тома.
Для пустого нового тома сначала подготовьте кэш, затем запускайте бот;
команда пересчёта требует существующий файл базы.

## Откат и ограничения

При остановленном polling проверьте копию и восстановите её командой
`database.backup restore КОПИЯ РАБОЧАЯ_БАЗА`, как описано в
[руководстве разработчика](DEVELOPMENT.ru.md#резервная-копия-и-восстановление-sqlite).
Затем верните **код E5**, например сохранённый коммит `878ceb5`, и его
зависимости/образ. Новый код FRIDA откажется искать по восстановленным E5-векторам.
Сохраните отдельную копию новой базы перед откатом, если появились новые решения.

Смена модели сделана по запросу владельца. Она не подтверждает улучшение
на независимой разметке: исторические метки остаются предварительными.
Пороги чатов, в том числе прежний стандартный 0.88, сохранены; это не
калиброванный порог FRIDA. Автоматического переноса экспериментального
порога или влияния голосов на поиск нет.

В проверке на 15 вымышленных случаях FRIDA при сохранённом пороге 0.88
не выдала подсказку ни для одного из 8 случаев с подходящим ответом
(один из них отклонён фильтром). Это не оценка на истории чатов, но явный
сигнал, что старый порог не следует считать настроенным для новой модели.

В прежнем прогоне на ПК полная FRIDA занимала около 3 ГиБ после запросов;
пик всего прогона — около 3.5 ГиБ. Это не гарантия размещения бота на VPS
с 4 ГБ, особенно с учётом ОС. VPS с 2–3 ГБ пока не подтверждён. Проверьте
холодный запуск, память и задержку пяти чатов на реальном сервере.
