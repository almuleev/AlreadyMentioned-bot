## Проверяемые варианты

Рабочий бот сохраняет закреплённую FP32 FRIDA и исходный контракт векторов.
Подготовлены три офлайн-варианта для сравнения на одинаковой версии истории:

1. `baseline`: текущий максимум сходства с вопросом или ответом.
2. `context_pair`: один поисковый документ `Вопрос: …\nОтвет: …`, кодируемый
   отдельно с `search_document:`. Старые векторы не заменяются.
3. `rerank_top5`: первые пять разных решений текущего поиска, до порога,
   повторно оцениваются закреплённым мультиязычным MiniLM ONNX по паре
   «новое сообщение / сохранённый вопрос вместе с ответом».

Дополнительно `rerank_recall_guard` выбирает порог оценщика с ограничением:
число правильных подсказок на ранней основной части не должно быть ниже
исходного поиска. Это сохраняет количество, но не гарантирует те же
правильные случаи или сохранение полноты дополнительного сценария.
Если условие невозможно, остальные отчёты сохраняются с объяснением.

Оценка повторного ранжирования показывает релевантность; она не является
вероятностью правильности или доказательством полноты ответа. Одна модель
FRIDA и один оценщик загружаются в офлайн-процесс. Во время эксперимента
рабочий контейнер продолжает использовать прежний поиск.

## Запуск

Нужны подготовленные локальные кэши FRIDA и оценщика, а также зависимости
из группы `rerank`. Скачивание при этом запуске не разрешено.

```powershell
$a = 'X:\Alex\My Projects\programs\Trash\data-for-AlreadyMentioned-bot\annotated'
.\.venv\Scripts\python.exe -X utf8 -m already_mentioned.search_experiment --datasets "$a\label_review_v3_20261006" "$a\label_review_v3_20261006\with_inferred" --split-cases "$a\bank_review_v2\reviewed_cases_full.csv" --output training_runs/search_improvements_repeat
```

`--output` должен указывать новую папку. JSON содержат контрольные суммы,
ID, оценки первых пяти кандидатов, показатели и контракты, без текстов
переписки и векторов. Предыдущие отчёты и CSV сохраняются.

Граница ранних 60% каждого чата заморожена по исходным ID до исключения
`UNRESOLVED`. Порог каждого варианта выбирается по F-beta 1.1 **только на
ранних основных случаях**. Он применяется без перенастройки к поздней
части и к сценарию с предполагаемыми организаторами. Это повторный
эксперимент на предварительных метках и уже знакомой истории, а не
независимый тест. Результаты разных версий меток не смешиваются.

## Просмотр

```powershell
$reports = Get-ChildItem training_runs/search_improvements_repeat/*.json | Select-Object -ExpandProperty FullName
.\.venv\Scripts\python.exe -m already_mentioned.model_results_viewer --reports $reports --datasets "$a\label_review_v3_20261006" "$a\label_review_v3_20261006\with_inferred" --output training_runs/model_viewer/search_improvements.html
```

Просмотр позволяет сравнить предложенный ответ и молчание, увидеть
альтернативы и оценить полноту кандидата. Ручные оценки экспортируются
отдельно и не переписывают метки автоматически.

## Диагностика нового сообщения

[Эксперимент с GTE от 8 октября](GTE_RERANKER.ru.md) проверил другого
оценщика на тех же пяти кандидатах. Смесь восстановила ранние ответы,
но увеличила поздние ошибки: 2 верных / 17 ошибочных / 5 пропусков
против 2 / 2 / 5 у смеси с MiniLM. Новые варианты остались офлайн.

```powershell
.\.venv\Scripts\python.exe -m already_mentioned.diagnostics --chat-id=-1001234567890 --top-k 5 "Где включить второй фактор?"
```

Подставьте ID своего чата. В Docker используйте `docker compose exec -T bot
python -m already_mentioned.diagnostics …` после обновления образа. Поиск
кандидатов читает только данный чат, кодирует запрос один раз, показывает
максимальный score и отдельные scores вопроса/ответа. База открыта только
для чтения. Команда не отправляет сообщения в Telegram.
