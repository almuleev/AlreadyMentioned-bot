# Просмотр реакций моделей

Сводные результаты прежних прогонов описаны в
[сравнении моделей](HISTORICAL_MODEL_COMPARISON.ru.md) и
[сравнении FRIDA FP32/INT8](FRIDA_QUANTIZATION.ru.md).
Для просмотра конкретных сообщений создайте локальный HTML из полных JSON
и исходных CSV той же версии. Устанавливать дополнительные библиотеки,
запускать модели или сервер не нужно.

```powershell
$p = 'X:\Alex\My Projects\programs\Trash\data-for-AlreadyMentioned-bot\annotated\bank_review_v2'
$reports = Get-ChildItem training_runs/bank_v2_model_comparison/*.json | Where-Object Name -ne 'summary.json' | Select-Object -ExpandProperty FullName
.\.venv\Scripts\python.exe -m already_mentioned.model_results_viewer --reports $reports --datasets $p "$p\with_inferred"
Start-Process training_runs/model_viewer/index.html
```

Готовый файл `training_runs/model_viewer/index.html` открывается в браузере
и работает без сети. Он содержит исходную переписку, поэтому остаётся
локальным и исключён из Git вместе с `training_runs/`.

Выберите сценарий, модели и сообщение в таблице. Внизу появятся исходное
сообщение, ожидаемые ответы по разметке и отдельная карточка каждой модели:
предложенный ответ или причина молчания, лучший кандидат, сходство, порог,
отрыв от второго кандидата. В раскрываемых блоках сохранены даты, ID,
авторство и контекст из CSV, контракт модели, время, память и хэш отчёта.
Для поиска ошибок используйте фильтр «Ошибки и пропуски», для сравнения
реакций — «Расхождения моделей». Таблица показывает по 100 сообщений.
Показатели пересчитываются на всех сообщениях, оставшихся после фильтров,
а не только на текущей странице. Неверная подсказка вместо ожидаемого
ответа одновременно считается ошибкой и пропуском.

По умолчанию показана поздняя часть истории; ранняя часть использовалась
для калибровки. Пробный общий порог позволяет изучить изменение реакции,
но не изменяет настройки бота и не становится новым результатом калибровки.
Шкалы разных моделей различаются. Разметка предварительная; выбор порога
после просмотра поздних сообщений не является независимой проверкой.

При подключении других прогонов укажите их полные JSON в `--reports`, а
папки исходных CSV в `--datasets`. Можно сравнить FP32 и INT8 из
`training_runs/frida_quantization_20261006/paired_single/`. Для одинакового
названия сценария инструмент требует одинаковые хэши CSV, метки, набор
сообщений, разбиение и результаты фильтра. Несовпадающие версии нужно
просматривать отдельно. Агрегатная сводка `summary.json` не подходит.

Это просмотр уже измеренной реакции на исторические сообщения. Ввод нового
сообщения здесь не запускает модель. В старых отчётах сохранён только
первый кандидат и отрыв: список альтернатив и отдельные сходства с
вопросом и ответом восстановить без нового прогона нельзя. У отрицательных
сообщений, отклонённых фильтром, модель не запускалась — отсутствие кандидата
не следует трактовать как оценку семантического поиска.

## Разбор улучшений поиска

Отчёты нового `search_experiment` дополнительно содержат пять кандидатов,
отдельные сходства с вопросом, ответом и текстом пары; у варианта повторного
ранжирования также записан score оценщика. В карточке раскройте «Пять
кандидатов и отдельные оценки». У старых отчётов этих сведений нет.

Для лучшего кандидата каждой модели выберите оценку полноты и при желании
напишите комментарий. «Сохранить оценки кандидатов» скачивает отдельный
`model_candidate_review.json` без текстов переписки, с ID сообщения/решения
и SHA256 отчёта. Если браузер не скачал файл, JSON можно скопировать из
появившегося блока и сохранить вручную в файл с расширением `.json`.
До сохранения оценки живут только в памяти страницы и теряются при
перезагрузке. При следующем открытии загрузите JSON через
«Продолжить проверку»; чужие или изменившиеся отчёты не принимаются.
Импорт объединяет оценки, совпадающие записи заменяются импортированными.
Оценки относятся к кандидату даже тогда, когда порог запрещает подсказку.
Они не меняют метки CSV, показатели таблицы, веса модели или голоса бота.

Критерий текущего выпуска: полный и содержательный частичный ответ оба
полезны. Итоговые метрики зависят от версии исходной разметки;
старые отчёты не пересчитываются при выставлении ручной оценки.

Три новых варианта и условия сравнения описаны в
[эксперименте улучшения поиска](SEARCH_IMPROVEMENTS.ru.md).
