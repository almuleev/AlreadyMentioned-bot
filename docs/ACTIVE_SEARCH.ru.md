# Рабочий поиск и проверка выпуска

8 октября 2026 года. Критерий владельца: полный и содержательный частичный
ответ — правильная подсказка; ответ на другой вопрос — ошибка. Приоритет
отдаётся полноте, пороги подбираются по основной ранней части по F2.

## Режимы и настройки

`SEARCH_MODE=hybrid` включает полную FP32 FRIDA и закреплённый MiniLM
`cross-encoder/mmarco-mMiniLMv2-L12-H384-v1`, ревизия
`1427fd652930e4ba29e8149678df786c240d8825`, файл `onnx/model_quint8_avx2.onnx`.
FRIDA выбирает пять кандидатов того же чата. MiniLM получает отдельный
запрос и сохранённые `Вопрос: …\nОтвет: …`, по одной паре на вызов,
512 токенов. Итог — 0,75 максимального сходства FRIDA + 0,25 оценки MiniLM.
Оценка не является вероятностью правильности или полноты ответа.

`SEARCH_MODE=baseline` включает прежний максимум сходств FRIDA с вопросом
и ответом. Для переключения пересоберите/перезапустите один процесс бота.
В Compose переменная читается из окружения или локального `.env`.
Кэш и сохранённые векторы FRIDA общие; повторное кодирование базы не нужно.

SQLite версии 5 добавляет отдельный nullable `hybrid_threshold` каждому чату.
Существующий порог FRIDA сохраняется. Пока новый порог чата не установлен,
используется калиброванное значение выпуска из `config.py`.
Текущий гибридный порог — **0,371**, выбран на ранних основных случаях по F2.
Исходный порог FRIDA — 0,458; эти оценки относятся к разным шкалам.
`/status` показывает активный режим и его порог. `/threshold ЧИСЛО`
изменяет только порог активного режима данного чата. Обновление названия
чата и `/forget` сохраняют оба порога.

## Подготовка и запуск

Локально установите дополнительную группу зависимостей: `pip install -e ".[rerank]"`.
Docker устанавливает её автоматически. До запуска должны быть готовы
оба закреплённых кэша. Минимальная подготовка MiniLM локально:
Compose задаёт `HF_HUB_OFFLINE=1`, чтобы загрузчики не проверяли сеть
при рабочем запуске. Подготовку отсутствующих файлов выполняйте отдельно
с разрешённым доступом к Hugging Face.

```powershell
.\.venv\Scripts\python.exe -c "from already_mentioned.services.reranking import OnnxReranker; OnnxReranker(batch_size=1).predict('Проверка', ['Проверка'])"
```

Для Docker выполните ту же проверку в отдельном контейнере с подключённым
томом `model_cache`; Windows-кэш сам по себе в контейнер не попадает.
При копировании кэша между Windows и Linux нужно сохранить корректные
относительные ссылки на blobs. Исходные Windows-файлы не изменять.

Перед обновлением создать и проверить копию SQLite через
`already_mentioned.database.backup`. Остановить предыдущий polling,
затем `docker compose up -d --build bot`. На старте прогреваются обе модели;
ошибка кэша останавливает запуск, вместо незаметной смены алгоритма.
Не запускать вторую копию бота с тем же токеном.

## Проверка всех сообщений без Telegram

Новая версия разметки `partial_answer_v4_20261008_02` содержит 3347 исходных
сообщений: 3305 известных меток и 42 неизвестных. В основном сценарии
51 положительный случай; изменена 31 прежняя метка. Явные ручные оценки
полных и частичных ответов применены с сохранением происхождения источников.
Метрики остаются предварительными: все отрицательные случаи не проходили
новую независимую исчерпывающую проверку. Банки ответов не импортируются
в рабочую базу.

Сравнение после новой разметки, пороги подобраны только на ранней части:

| Вариант | Порог | Ранняя F2 | Поздние правильные | Ошибки | Пропуски |
| --- | ---: | ---: | ---: | ---: | ---: |
| FRIDA, исходный максимум | 0,458 | 0,532 | 7 | 4 | 10 |
| FRIDA, вопрос и ответ вместе | 0,440 | 0,525 | 10 | 10 | 7 |
| FRIDA + MiniLM, смесь 75/25 | **0,371** | **0,566** | **10** | **8** | **7** |
| MiniLM, одиночные пары без смеси | 0,050 | 0,387 | 8 | 36 | 9 |

Выбрана смесь 75/25 по максимальной ранней F2 из девяти вариантов.
В основной поздней части полнота выросла с 41,2% до 58,8%, точность
подсказок снизилась с 63,6% до 55,6%. Это компромисс в пользу ответа,
не устранение ошибок. В отдельном сценарии с предполагаемыми организаторами
при том же пороге: 11 правильных, 11 ошибок, 7 пропусков; он не участвовал
в подборе. Агрегаты и хэши: [отчёт](experiments/active_search_3347_20261008.json).

Из семи поздних пропусков гибрида четыре связаны с фильтром сообщений,
один — с выбором кандидата, два — с порогом. Следующее улучшение качества:
проверить расширение фильтра на всей выборке, включая новые отрицательные
сообщения, затем выполнить независимый разбор неподходящих подсказок.

`already_mentioned.release_validation` использует настоящий `SearchService`,
полную FRIDA и MiniLM, но не использует токен, рабочую SQLite или Telegram.
Решения доступны только после даты исходного ответа в том же чате.
Исполняются все 3347 сообщений версии разметки; 42 неизвестных не входят
в метрики. Порог задаётся из предварительной ранней калибровки, здесь
не подбирается. В отчёте — качество, время реального кодирования запроса
и повторного ранжирования, совместная память и пик всего процесса.

```powershell
.\.venv\Scripts\python.exe -m already_mentioned.release_validation `
  --dataset DATASET --output NEW_JSON --mode hybrid `
  --baseline-threshold BASELINE_THRESHOLD --hybrid-threshold HYBRID_THRESHOLD
```

Подставьте путь к версии разметки и пороги её отчётов. Изолированный запуск
Docker с `--cpus 2 --memory 4g --network none` проверяет реальные локальные
лимиты, но не воспроизводит Telegram или конкретный VPS. Прогретое время
не включает Telegram, чтение рабочей SQLite или ожидание общей очереди.
Среднее и p95 относятся к прошедшим фильтр сообщениям, для которых уже
существует хотя бы одно доступное решение. Ранние сообщения с пустым банком
исполняются, но не снижают эту оценку времени нулевыми запросами.

Полный рабочий повтор завершился с кодом 0, без OOM, при ограничениях
2 CPU и 4 ГиБ RAM, с отключённой сетью и кэшем моделей только для чтения.
Все 3347 строк исполнены; итог на 3305 известных метках — 34 правильные
подсказки, 60 ошибок и 17 пропусков. Поздний результат 10/8/7 и ранний
24/52/10 совпали с одиночной абляцией гибрида. Ответ на положительный случай
неверным решением считается и ошибкой, и пропуском нужного решения.

Обе модели загрузились за 5,91 с. Из 999 прошедших фильтр сообщений
974 имели доступный банк: среднее 471,8 мс, p95 688,6 мс. RSS после
совместной загрузки — 3,42 ГиБ; максимум выборок после запросов — 3,67 ГиБ;
пик всего процесса по Linux `getrusage` — 3,67 ГиБ. Выборки после запросов
не гарантируют измерение пика внутри каждого вызова. Эти цифры относятся
к данному локальному Docker-хосту, не к Telegram или отдельному VPS.
Разбор причин пропусков выше взят из абляции, сохранившей лидеров до порога;
рабочий повтор хранит только реально выданные ответы.

## Откат

Оперативный откат — `SEARCH_MODE=baseline` и перезапуск текущей версии.
Она поддерживает SQLite версии 5 и прежний порог FRIDA.
Образ до миграции понимает схему только до версии 4: его нельзя запустить
на новой базе. Для полного отката к нему нужны остановленный бот и
проверенная копия базы до обновления. Восстановление копии теряет изменения,
сделанные после её создания; обычное переключение режима их сохраняет.
