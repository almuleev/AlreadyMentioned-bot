# Проверка квантованной FRIDA — 6 октября 2026

Показатели ниже относятся к CSV версии 2. Последующий
[повторный аудит разметки](LABEL_REVIEW.ru.md) создал отдельную кандидатную
версию с изменёнными SHA256; эти показатели не являются оценкой новой версии.

## Условия

Сравниваются полная `ai-forever/FRIDA` и эксперимент `frida-int8` из одной
ревизии `850455b605544a944739b25f81ddf812b6e3d0d5`. Оба используют
`search_query:` / `search_document:`, CLS, L2, 1536 компонентов, выход
float32 и максимум сходства с вопросом и ответом. В INT8 переведены 168
линейных слоёв, остальные параметры сохраняют FP32. Backend — oneDNN,
PyTorch 2.14.0+cpu. Исходный кэш не изменён; все векторы эксперимента
получены заново каждым вариантом. Совпадение размерностей не означает
совместимость этих пространств.

Использована динамическая конверсия
[`torch.ao.quantization.quantize_dynamic`](https://docs.pytorch.org/docs/main/generated/torch.ao.quantization.quantize_dynamic.html).
Этот API помечен устаревающим; эксперимент ещё не является готовым
форматом модели для развёртывания.

Основной набор: 3216 сообщений, 127 решений, 32 положительных случая.
Дополнительный сценарий: 136 решений и 36 положительных случаев с
добавлениями от предполагаемых организаторов. SHA256 всех CSV совпадают
между вариантами. Метки не изменялись. Пороги отдельно подбираются по F1
на ранних 60% каждого чата (1928 случаев); поздние 40% (1288) оцениваются
с уже выбранным порогом. В поздней части всего 12/13 положительных случаев.
Разметка предварительная, без независимого подтверждения владельцем;
эта поздняя часть уже использована в нескольких экспериментах.

Парный прогон: AMD Ryzen 5 5600X (6 ядер / 12 потоков), два CPU-потока
модели на текущем Windows-ПК, отдельный процесс
для каждого варианта, 985 уникальных запросов и 271 сохранённый текст.
Все запросы и тексты банка кодируются **по одному**. Состав пакета может
влиять на динамическое квантование, поэтому результат с пакетом 16
нельзя напрямую использовать как результат автосохранения.

Полные JSON, журнал и очередь изменившихся решений остаются локально;
сводка без переписки: [JSON](experiments/frida_quantization_20261006.json).
Команда повторения описана в [инструкции разработчика](DEVELOPMENT.ru.md).

| Основной / INT8 | 0,47724 | 4 | 5 | 8 | 44,4% | 33,3% | 38,1% |

В основном сценарии сохранились **те же** четыре правильные подсказки.
В дополнительном потерян один поздний правильный ответ без приобретения
другого. Лидер сохранился правильным, но его score упал с 0,52748 до
0,47388 и оказался ниже выбранного на ранней части порога 0,47724.
Порог не снижался по этому уже увиденному позднему случаю. В обоих
сценариях фильтр отсеивает четыре положительных случая поздней части;
квантование фильтр не меняет. Число положительных случаев с правильным
лидером без фильтра осталось 10/11; один неверный лидер — в каждом
сценарии. Дополнительный пропуск INT8 возникает на пороге.

На всём наборе FP32 → INT8: основной 12/54/20 → 12/38/20;
дополнительный 13/42/23 → 14/44/22 (верные/ошибки/пропуски).
Итог всей истории скрывает потерю позднего ответа: два приобретённых
правильных случая дополнительного сценария находятся в ранней части.
Всего 29 изменившихся решений включены в локальную очередь проверки;
метки автоматически не исправлялись.

## Время и память

| Измерение | FP32 | INT8 |
| --- | ---: | ---: |
| Загрузка и подготовка | 6,14 с | 26,72 с |
| Один прогретый запрос, среднее / p95 | 354,8 / 527,4 мс | 237,9 / 336,3 мс |
| Один сохранённый текст, среднее | 374,4 мс | 233,6 мс |
| Перебор 15 / 50 / 100 / 200 решений, среднее | 0,58 / 1,63 / 3,00 / 6,21 мс | 0,56 / 1,47 / 2,90 / 5,76 мс |
| RSS после 985 запросов | 3009,8 МиБ | 2374,5 МиБ |
| Максимальный RSS, замеренный после отдельного запроса | 3513,6 МиБ | 2375,2 МиБ |
| Пик RSS всего процесса | 3513,8 МиБ | 5407,4 МиБ |

Запрос в среднем быстрее на 33%; RSS после запросов ниже на 21%.
Замеры после вызовов не гарантируют обнаружение пика **внутри** запроса.
Холодный пик INT8 — 5,28 ГиБ: процесс сначала загружает FP32, затем
конвертирует слои. Готового переносимого INT8-файла пока нет.
Следовательно, этот способ старта ещё не подтверждён для 4 ГБ RAM.

Первый прототип, без освобождения общего хранилища оставшихся FP32
параметров и с пакетом 16, потреблял 4491 МиБ к концу прогона и имел пик
4752 МиБ — хуже полной модели. В парном прогоне оставшиеся FP32 параметры
скопированы в собственное хранилище с сохранением значений, чтобы не
удерживать исходное отображение checkpoint в памяти. Скопировано
575 695 872 байта. Рабочий RSS снизился, но временный пик вырос.
Первый отчёт сохранён как отдельная неудачная попытка; его качество не
подменяет результат парного сравнения с пакетом 1.

## Пять чатов

Шесть групп по пять запросов, каждая приходит раз в пять секунд:
30 запросов, длинные вопросы 189–510 символов, 200 пар решений своего чата.
Все сообщения проходят фильтр, повторное кодирование выполняется без кэша.

| Задержка от поступления сообщения | FP32 | INT8 |
| --- | ---: | ---: |
| Среднее | 2,83 с | 1,71 с |
| p95 | 4,35 с | 2,68 с |
| Максимум | 4,76 с | 2,72 с |
| Максимальное ожидание очереди | 4,22 с | 2,37 с |

За эти шесть групп нарастающей очереди не было: начальное ожидание
последней группы меньше 1 мс в обоих вариантах. Это короткая проверка
на ПК, без одновременного автосохранения и сетевых задержек.

## Сохранение и проверки

Полные отчёты находятся в
`training_runs/frida_quantization_20261006/paired_single/`;
`changed_decisions_review.csv` содержит исходный контекст для проверки
владельцем и остаётся вне Git. Копии результатов сохранены рядом с
разметкой в `annotated/frida_quantization_20261006/`. Аудит повторно
рассчитал пороги и все показатели из деталей, проверил входные SHA256,
совпадение случаев, меток, фильтра и разбиения. Сводка в Git содержит
версии библиотек, хэши полных отчётов и агрегаты без переписки и ID случаев.

Ruff — без ошибок; pytest — **112 тестов**. Новые проверки охватывают
INT8 backend и полноту конверсии, сохранение FP32 значений, префиксы и
ревизию, пакет из одного текста, ошибки аргументов CLI и задержку очереди
при нормальной нагрузке и перегрузке. Тесты не скачивают модели.

## Ограничения выпуска

**Замена пока не рекомендуется:** дополнительный сценарий ухудшился,
а холодный пик не укладывается в заявленный объём 4 ГБ по измеренному RSS.
Бот по-прежнему использует E5 small, рабочая база и её embeddings не
изменены. Порог FRIDA нельзя переносить на E5. Даже сохранение числа
верных ответов не подтверждает достаточное качество: нужно проверять
ошибочные подсказки и утраченные отдельные случаи.

Docker daemon недоступен. Проверка с принудительным лимитом 2 CPU / 4 ГБ
не выполнена; запуск Docker Desktop может автоматически поднять другие
контейнеры, поэтому он не запускался. Измерения ПК не доказывают работу
на VPS. Нагрузочный тест исключает Telegram, SQLite, автосохранение и
расходы ОС; повторение банка до 200 пар проверяет время, не качество.

Перед выпуском нужны проверка на целевом сервере, запас памяти для ОС и
бота, независимая разметка новых случаев и пригодный артефакт квантованной
модели. Замена рабочей модели потребует резервной копии, явной миграции
контракта и полного пересчёта вопросов и ответов с проверкой и откатом.
